## 11:38 — PR: feat(m5.5): app home page and editor navigation menu (#518)

This PR delivers the M5.5 navigation polish milestone: a proper app home page at `/`, a shared
editor navigation bar across all four dev-tool pages, and the `menu-bg.png` background image
applied consistently to the home page and the lobby. Before this change, visiting the app root
landed on a developer status widget that was never intended as a player-facing entry point.

The home page (`HomeView.vue`) wraps two menu buttons — Lobby and Editor — in a styled card
over the full-bleed background image. The Editor button is gated on `VITE_MAP_EDITOR_ENABLED`:
when editors are disabled it navigates to `/lobby` rather than to an unmounted tool route. This
reuses the `VITE_MAP_EDITOR_ENABLED` pattern already present in `StatusView`; the main
housekeeping change was adding the `VITE_` prefixed var to `.env.example` alongside the
server-side `MAP_EDITOR_ENABLED` flag so that new developers know to set both.

`EditorNav.vue` is a thin nav strip mounted at the top of MapEditorView, OobEditorView,
MapTestView, and TableTestView. When editors are enabled it shows links to all four tools plus
a Home escape hatch; when disabled only the Home link renders. The four existing view test
files each gained a single `vi.mock` stub for `EditorNav` — the same approach already used for
`HexMapOverlay` in those files — to avoid `RouterLink` injection errors in jsdom without a
router plugin.

One non-obvious constraint surfaced during implementation: adding `VITE_MAP_EDITOR_ENABLED=true`
to the local `.env` caused `StatusView.test.js` to start rendering its `dev-tools` section, which
broke four tests that had been mounting `StatusView` without a router plugin. The fix was twofold:
pass `stubRouter` to all four mounts, and convert the "hidden when disabled" test to use
`vi.stubEnv` + `vi.resetModules` for proper isolation. The LobbyView background was implemented
as a new `.lobby-bg` wrapper div so existing tests on the inner `.lobby` selectors required no
changes.

Nothing was deferred from the issue scope. The `ScenarioEditorView` is intentionally excluded
from `EditorNav` per the spec (not in the issue's editor menu requirements). The track
`home-nav-menu_20260607` is closed; all 14 tasks complete, `quality:strict` clean at 2529 tests.
