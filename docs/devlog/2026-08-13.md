## 02:16 — PR: Map Data Debt Sprint — Issues #693-696

This PR closes the four tracked-debt items `/team-review` surfaced on PR #692
(map-col64-investigation_20260812): a missing regression test for
`gridSpec.cols`, a non-blocking `validate-data.js` check with no test
coverage of its own, an undocumented and unenforced `playable` schema field,
and South Mountain map-status facts duplicated by hand across multiple
documentation locations. All four were low-to-moderate score items (2 each,
8 total) filed under the project's Immediate Debt-Capture Policy rather than
folded into #692 itself, which was correctly scoped narrowly to the
`gridSpec.cols` config fix.

The `#693` fix (`server/src/engine/map.test.js`) turned into the most
interesting phase: the first invariant drafted — every recorded hex falls
within `[1, cols] x [1, rows]` — was itself wrong. The real map data records
boundary-marker hexes at row 0 and row 36 (`playable: false`), one row
outside the declared `gridSpec.rows: 35`, matching the same north/south-edge
convention `map-col64-investigation_20260812` considered (and rejected) for
column 64. The test was corrected to allow that documented exception rather
than asserting a stricter invariant than the data actually follows.
Mutation-testing (temporarily reverting `gridSpec.cols` to 64 in a scratch
copy) confirmed the new test catches the exact #691 regression class.
Investigating #693 also surfaced a second, more concrete instance of the
same risk the issue described: `client/src/utils/calibration.js`'s
`DEFAULT_CALIBRATION.cols` was still `64` — a live write path, since the Map
Editor seeds calibration from `localStorage` before any server load. Fixed
inline after checking with the user, since it was a one-line, low-risk
change directly tied to the issue's stated root cause. Fixing it also
surfaced that `useCalibration.test.js` had its own hand-copied duplicate of
`DEFAULT_CALIBRATION` — exactly the drift class this whole track exists to
guard against — replaced with a real import.

`#694`'s fix promoted `validate-data.js`'s grid-coverage check from `warn()`
to `fail()`: a coverage gap silently opens phantom grid cells to the
pathfinder, since `hex.js` gates reachability purely on `gridSpec` bounds, so
this was a correctness hazard rather than a cosmetic one. The three checker
functions in scope (`checkSetupHexesInMap`, the new `checkGridCoverage`, and
`checkEdgeFeatureTypesRegistry`) were extracted to named exports, and the
script's main execution was guarded behind an `import.meta.url ===
process.argv[1]` direct-run check so `scripts/validate-data.test.js` can
import them for testing against small in-memory fixtures without triggering
a full run (real file loads, `process.exit`) as a module side effect.

`#695` added a scope comment to the schema's `playable` field (matching the
`ELEVATION_TYPES` export comment style) plus a characterization test in
`movement.test.js` pinning that the field is not consulted by the
movement/pathfinding engine — a deliberate documentation choice, not a
silent gap. Actually enforcing `playable: false` as impassable terrain
remains explicitly out of scope, since that's a rules-behavior change
requiring domain-expert sign-off, not a debt-cleanup fix.

`#696` added `scripts/library-sync.test.js`, asserting `docs/library.json`'s
`SM_MAP_DATA.hexCount` and `status` fields stay in sync with
`data/modules/south-mountain/map.json`'s real `hexes.length` and `_status`,
so a future map edit that forgets to update `library.json` fails CI instead
of silently going stale. Per the approved spec, only two of the seven
duplication locations were trimmed to point at `docs/library.md` instead of
independently restating counts — `high-level-design.md`'s risk-register row
and `domain-expert/design.md`'s `SM_MAP_DATA` row — leaving `docs/library.md`
itself as the intended human-readable source of truth, plus `CLAUDE.md` and
HLD's other two mentions untouched as agreed out-of-scope.

The full quality suite (`validate-data`, `lint`, `format:check`, `test` —
160 files / 3277 tests, `build`) is green throughout, with one pre-existing
accepted-noise warning (`longstreet` commandsId) unrelated to this track.
This track ran in Checkpointed mode per the project's quality rails (touches
a data validation schema and the build-gate script), with a human checkpoint
before promoting the `validate-data.js` check to a hard failure.
