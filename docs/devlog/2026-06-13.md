# 2026-06-13

## 08:44 — PR: Pre-M6 Debt Sprint — Score 3+ and Low-Hanging Fruit

This PR completes a pre-M6 housekeeping sprint targeting all open debt items scored 3 or higher plus a selection of easy score 1–2 items. The net open debt score drops from 41 to 31 — not yet below 15, but all the high-risk structural items are resolved before combat, morale, and orders work begins in M6.

The highest-priority fix was #540: `moduleData.js` PUT/POST/DELETE routes were mounted unconditionally, meaning any origin that passed the CSRF check could overwrite data files at `/api/v1/modules/:slug/*`. The fix adds a middleware guard at the top of the router that returns 404 for non-GET requests when `MAP_EDITOR_ENABLED` is not `'true'` — identical to the guard already used for other editor routes in `server.js`. All existing PUT tests were updated to set the flag; two new guard tests confirm the behavior in both directions.

Issue #541 addressed a silent correctness hazard in `useOobPersistence`: when called without a `moduleSlug`, the composable fell back to legacy `/api/tools/*` URLs without any indication that it was doing so. Push operations would silently write to the wrong endpoints. The fix adds a `console.warn` in `buildUrls` so the fallback is no longer invisible. Full removal of the legacy path was not done because `useOobStore` still calls `loadData()` (no slug) as a standalone fallback when the route has no `moduleSlug` param. That codepath remains valid for the legacy tool entry point. The warning makes misdirected writes detectable without breaking existing behavior.

For #531, `MINUTES_PER_CONDITION` lived only in `ScenarioEditorView.vue` while `engine/init.js` hardcoded `15` with a comment noting the limitation. Extracting to a shared module was complicated by the client/server split: Vite's security model blocks imports from outside the client root, so a single shared file isn't feasible. Instead, two sister files were created — `server/src/engine/turnTime.js` and `client/src/config/turnTime.js` — both exporting identical constants with a cross-reference comment. The `?? 15` fallbacks in the view were replaced with `?? MINUTES_PER_CONDITION_DEFAULT`, also exported from the config.

The Phase 3 low-hanging-fruit work added `VISIBILITY_UNLIMITED = 999` to eliminate the magic sentinel value; an upper-bound refine on `visibilityHexes` (1–20 or 999); a `.superRefine` uniqueness check on `lightingSchedule` `startTurn` values; and five new test cases covering `totalTurns` edge cases (empty schedule, inverted time range, missing `firstTurn`) and the `lightingStartTimes` night-turn clock accumulation. Direct URL construction tests were also added for both `useMapPersistence` and `useOobPersistence`. Issue #533 (removing `totalTurns` from `scenario.json`) was deferred: the field is required in the Zod schema and present in all nine module data files, making it a schema migration rather than a simple cleanup.

## 10:32 — PR: Pre-M6 Debt Sprint #2 — Debt, Doc Sync, Stubs

This PR closes four remaining score-2 debt items (#542, #545, #546, #533), updates all eight non-South-Mountain module stubs with real game names, and syncs the project documentation to the M5.5-complete state. It is the second of two back-to-back debt sprints run before M6 combat work begins, bringing the net open debt score from 23 to a level where all medium-risk items are resolved.

Phase 1 tackled the four code-level debt items. The most architecturally meaningful was #542: all three editor views (`ScenarioEditorView`, `MapEditorView`, `OobEditorView`) were capturing `route.params.moduleSlug` as a plain string at setup time rather than wrapping it in `computed()`. This meant in-page navigation that changed the slug without a full component remount would silently use stale values. The fix wraps all slug captures in `computed(() => route.params.moduleSlug)` and threads `unref()` into `useMapPersistence` so the composable accepts both plain strings and reactive refs. For #545/#546, `ModuleNotFoundError` (already defined in `server/src/utils/moduleFolders.js` with `this.status = 404`) was not wired into any central error handler — each route had to inline its own try/catch. A global `(err, req, res, next)` Express error handler is now registered in `server.js` after all routes, returning `{ error: 'Not found' }` for `ModuleNotFoundError` and `{ error: 'Internal server error' }` for anything else. Issue #533 completed the `totalTurns` migration started in PR #548: the field was made `.optional()` in `ScenarioSchema` (with a deprecation comment) and removed from the South Mountain `scenario.json` — the client derives turn count from `firstTurn`/`lastTurn` at runtime.

Phase 2 updated all eight non-SM scaffold `scenario.json` files with real game names, correct publications, and a `_battle` field. Previously these stubs had generic placeholder names (`"Scenario Name"`) that made the module selector unreadable. The `_status: "scaffold"` marker is preserved so the system knows none of these modules have real OOB, map, or game data yet. All nine modules pass `npm run validate-data` with the `totalTurns` now optional in the schema — the eight scaffold files still have the field and it continues to validate cleanly.

Phases 3 and 4 were documentation-only. `docs/designs/high-level-design.md` was updated with a full M5.5 completion entry in the implementation status callout, the milestone table row moved from `🔜 Next` to `✅ Done`, and M6 promoted to `🔜 Next`. The domain-expert agent design doc received three additions: an "Implemented Rule References" table covering the LOB §6.1 visibility sentinel, the LOB §1.1 fog/rain duration inheritance, the derived `totalTurns` removal, and the `lightingSchedule` uniqueness enforcement; a sister-module constants table so future agents know both files must be updated together; and corrected data file paths pointing to `data/modules/south-mountain/` rather than the old `data/scenarios/south-mountain/` layout.
