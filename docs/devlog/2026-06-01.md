# 2026-06-01

## 12:06 — PR: Fix leader counter upload in OOB editor (#484)

This PR closes issue #484, which was filed after PR #475 added fallback counter rects for leader units whose `counterRef.front` is null. Pleasonton, D.H. Hill, G.B. Anderson, Garland, and other leaders were appearing on the game map as labeled placeholder rectangles because no real counter image had been assigned. The OOB editor had no working path to upload and link an image for them.

Investigation revealed two root-cause gaps. First, when a leader node is clicked in the OOB tree, `selectNode` in `useOobStore` called `findNodePath(oob.value, node.id)` — but leaders live in `leaders.json`, not `oob.json`, so this always returned null. Because `OobDetailPanel` guards the `CounterImageWidget` behind `v-if="nodePath"`, the widget was never rendered for any leader node at all. The fix extends `selectNode` to fall back to `findNodePath(leaders.value, node.id)` and prepend `leaders.` to the result, producing paths like `leaders.union.army.0`. The existing `updateField` routing already handled paths with this prefix correctly.

Second, even with a valid path, the regular front/back slots in `CounterImageWidget` only cycle through the static `countersManifest.js` — there is no upload button for the `front` field. Leaders whose counter image files don't exist in the manifest yet (because they've never been digitized) had no upload path. The solution adds `Browse…` buttons to the front and back slot footers when `mode === 'leader'`, wired to the existing `POST /api/tools/counters/upload` endpoint via a new `onStandardFileSelected` handler. This mirrors the promoted-slot upload pattern already present in the component. A distinct `standard-file-input` class was used for the hidden file input to avoid selector conflicts with the pre-existing `promoted-file-input` — an important detail that surfaced when existing tests started finding the wrong inputs.

One known limitation: after uploading a new counter file, it won't appear in the `ALL_COUNTERS` cycling list within the current dev session because `countersManifest.js` is regenerated at Vite startup, not at runtime. The OOB editor thumbnail will show a placeholder until the next restart; the game map, which doesn't use the manifest, will display the real counter correctly on next load. This is a pre-existing constraint of the manifest architecture and is not introduced by this PR.

Eight new tests were added (two store unit tests for the `selectNode` path fix, six widget tests for the standard upload flow), bringing the total to 2363 passing across 129 test files.
