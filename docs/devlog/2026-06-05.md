## 17:21 — PR: OOB Editor display/data bugs (#506)

This PR closes four bugs in the OOB Editor that surfaced during M6 pre-work. All four are in M2–M5 surfaces that had been working but had subtle gaps: two in `OobDetailPanel.vue`, one in `oobTreeTransform.js`, and one spanning the transform, the tree node component, and `oob.json` itself.

The `specialRules` textarea bug (Bug 4) was the simplest: `leaders.json` stores `specialRules` as a JSON object, but the textarea binding used `:value="node.specialRules ?? ''"` which coerces objects to `"[object Object]"`. The fix adds a `specialRulesDisplay()` helper that calls `JSON.stringify(node.specialRules, null, 2)` when the value is an object, and an `onSpecialRulesChange()` handler that attempts `JSON.parse` on save with a plain-string fallback. Plain string values (and `null`) pass through unchanged, so existing string-typed `specialRules` entries are unaffected.

The Walker (Promoted) phantom node (Bug 3) was a defensive fix against a class of data error rather than a live regression: if a succession variant in `succession.json` were accidentally given a non-null `commandsId`, `buildLeadersMap` would index it as a unit leader and it would appear as a real brigade commander in the tree, displacing the real leader. The fix restructures `buildVariantsMap` to return both the `map` and a `variantIds` Set, then threads `variantIds` into `buildLeadersMap` so variant IDs are never indexed regardless of their `commandsId` value. A regression test verifies this case explicitly.

The AotP HQ "path not resolvable" bug (Bug 2) required the most coordinated change. The AotP HQ node is a synthetic object injected by `buildDisplayTree` — it has no real entry in `oob.json`, so `findNodePathInTree` always returns null for it, causing `OobDetailPanel` to show the fallback error instead of the counter widget. The fix adds a real `union.hq` entry to `oob.json`, reads it in the transform via `sideData.hq`, attaches `_nodePath: 'union.hq'` to the synthetic `_hq` node, and teaches `OobTreeNode` to forward `node._nodePath` as the third argument to `store.selectNode` when present. The store already accepted an explicit path as its third argument — no store changes were needed. The `UnionOOB` Zod schema was updated to allow an optional `hq` field so `validate-data` stays green.

Bug 1 (Supply/HQ missing back-counter slot) was investigated and found to not require a code change: `CounterImageWidget` always renders both front and back slots regardless of the `mode` prop — the `mode="leader"` guard only controls the promoted counter row. The issue description's root-cause hypothesis was incorrect. The back slot works correctly for all HQ and supply nodes that have a resolvable path (which Bug 2's fix now extends to the AotP HQ).

## 18:04 — PR: Debt sprint Phase 1 — test gap closures (#508 #509 #510)

This PR closes the first phase of the debt-sprint-to-10 track, targeting three test-quality issues from the PR #507 team-review that all turned out to share a root pattern: tests that exercised the right assertion but used fixtures that couldn't actually reach the code being guarded.

The most impactful fix was #508a — the `#506-3` variant guard test. The previous test put `walker-promoted` in the `succession` fixture only, but `buildLeadersMap` only reads from `leaders[side]`, never from succession data. The variant could therefore never enter `leadersMap` regardless of whether the `!variantIds.has(l.id)` guard was present, making the test completely inert. The fix creates a new fixture where `walker-promoted` appears as an entry in `leaders.confederate.brigades` with the same `commandsId: 'wj'` as the real Walker. A mutation test confirms the guard removal now makes this test fail.

The `_nodePath` forwarding gap (#508b) was straightforward — `OobTreeNode.handleSelect` was changed in PR #507 to pass `node._nodePath ?? null` as the third argument to `store.selectNode`, but no test asserted the path was forwarded. Two tests now cover both the forwarding case (explicit path flows to `store.selectedNodePath`) and the null case (absent `_nodePath` resolves via `findNodePathInTree`, returning null for a store with no oob data loaded).

The `JSON.parse` scalar gap (#508c) was a correctness issue: `onSpecialRulesChange` would store any successful `JSON.parse` result, including numbers, booleans, and null. The fix narrows acceptance to plain non-null non-array objects; any other parse result is stored as the raw string. A parametrized test covers five scalar/array inputs. #509 adds a path-pinning test that navigates the hardcoded `'union.hq'` string against a real `oob.json`-shaped fixture to prove the literal matches the actual data key — this test will break if the schema key is renamed. #510 adds the `null` display assertion and uses a distinct fixture id to discriminate the real-entry and fallback branches of the AotP HQ test.
