## 19:17 — PR: M6 Combat Engine — Fire, Melee, Morale, Rally

This PR delivers the `m6-combat-engine_20260614` Conductor track — the full M6 milestone wiring fire combat, close combat, morale cascade, leader casualty resolution, and Rally Phase CBF clearing into the live game dispatch pipeline. It is the largest single engine PR to date: 12 new handler/engine files, ~3,900 lines net added, `GameStateSchema` bumped to v3, and the morale state vocabulary unified across schema, tables, engine, and client.

**Schema changes (v3):** `UnitStateSchema` gained `depletionMarker` and `cbfMarker` booleans. `PendingResolutionSchema` extended with `combatResult`, `closingRoll`, `moraleCheck` types. `activityPhase.currentActivation` promoted from a bare hex string to `{ hex, movedThisActivation, openingVolley, zeroRuleFired }` to track activation history needed for Opening Volley gating. `rallyPhase: { unitsPendingRally }` envelope added, parallel to the existing `activityPhase`/`ordersPhase` pattern. All morale state codes renamed from short abbreviations to full English words (`'NM'` → `'normal'`, `'BL'` → `'bloodlust'`, `'SH'` → `'shaken'`, `'DG'` → `'disorganized'`, `'RT'` → `'routed'`) — eliminating the translation maps that had lived between the schema and table layers.

**New handlers:** `FIRE_COMBAT` (LOB §5) — validates activeness, weaponClass, side affiliation via `buildUnitSideMap()`, applies Opening Volley on move-then-fire, calls the combat table, sets `depletionMarker`/`cbfMarker`, and returns a `combatResult` pending resolution. `CLOSE_COMBAT` (LOB §7) — validates adjacency and enemy defender, fires defender OV on charge, applies automatic 1 SP defender loss, returns a `closingRoll` pending. `RESOLVE_MORALE` (LOB §6) — resolves a `combatResult` pending by applying the player-supplied dice to all units in the defender hex via the new `engine/morale.js` module, then sets `leaderCasualty` or cascade pending as appropriate. `RESOLVE_LEADER_CASUALTY` (LOB §9.1a) — resolves wounded/killed/captured outcomes and advances succession. `drainAutoSteps` Rally stub replaced with real CBF clearing; Fluke/Recovery stubs enumerate stopped/attack-order units (M7 TODO for actual resolution). `buildUnitSideMap()` added to `engine/oob.js` as the canonical OOB side-affiliation index.

**Team-review findings and disposition:** A full six-dimensional team review (security, architecture, testing, maintainability, domain, performance) surfaced four Critical and seven High findings. Three easy fixes were applied in-place: removed `void unitSideMap` dead code from `resolveMorale.js`, corrected a misleading `resolvePendingMorale` docstring that claimed `closingRoll` support, and fixed a "Defensive Ground" label conflation in `tables/morale.js`. The remaining eleven findings were deferred to M7 with filed GitHub issues (#571–#581), covering the two most significant domain bugs: (a) fire combat SP column incorrectly uses the **defender's** SPs instead of the attacker's (LOB §5.1), and (b) Opening Volley direction is reversed — the code models the attacker firing, where rules require the inactive defender to fire at the moving attacker (LOB §5.4a). Also deferred: CBF trigger too broad (#576), cascade hex-scope vs brigade hierarchy (#577), Rally §6.4 recovery rules (#578), close-combat 1-SP gate (#579), missing `resolveMorale.test.js` (#580), and the `dispatch()` wiring gap that leaves LOS validation dead in production (#572).

**Key design constraint:** The dispatch signature `handler(state, { type, payload, playerSide })` passes no third context argument, so the `{ oob, scenario, mapData, hexIndex }` injection seam that all three combat handlers declare is never populated in production — every handler falls through to synchronous `loadOob()` disk reads and Manhattan distance fallback for range. This was a known gap noted for M7 (#572). The DI seam is correctly wired in tests (handlers called directly), which is why the test suite is green despite the live pipeline gap.
