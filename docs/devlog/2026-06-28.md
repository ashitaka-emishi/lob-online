## 03:09 — Discord OAuth Identity Layer (M9 Track m9-discord-oauth)

Implemented the full Discord OAuth identity layer across three phases: server auth plumbing, SQLite schema migration, and client integration. The implementation is gated by two separate env-var switches — `DISCORD_CLIENT_ID/SECRET/CALLBACK_URL` for the real OAuth flow, and `AUTH_DEV_MODE=true` for a poorman local alternative (`POST /auth/dev/login { code }`) that creates a synthetic session without any Discord dependency. Both paths share the same passport session infrastructure and `deserializeUser` lookup, so the client cannot distinguish between them.

The SQLite migration was the highest-risk surface. The `gameSqlite.js` store already used a `user_version` pragma pattern, so the v1→v2 migration followed the same convention: a guard block that handles both v0→v2 and v1→v2 paths with idempotent `CREATE TABLE IF NOT EXISTS` and column-existence checks. The `users` table stores Discord ID, username, and avatar hash. Games now carry `side_a_user_id` and `side_b_user_id` FK columns, and `listGamesByUser(userId)` is the new primary query used by the games route instead of the old `listGames()` catch-all. The old `listGames()` is kept to avoid breaking any internal callers.

`requireAuth` middleware is applied at the router-mount level in `server.js` rather than inside the router file itself. This means the games router unit tests bypass it naturally — test isolation is preserved by injecting a `req.user` stub in `buildApp()`. This was a deliberate choice to keep the middleware composable and avoid coupling the router file to a specific auth strategy.

On the client side, a standalone `useAuthStore` Pinia store calls `GET /auth/me` once on first navigation to an auth-required route via a `beforeEach` guard. The `initialized` flag prevents redundant fetches across navigations. `HomeView` shows a Discord login anchor (`<a href="/auth/discord">`) when logged out, and disables the Lobby and Editor nav buttons as `<span aria-disabled="true">` elements rather than hidden elements — so the layout is stable regardless of auth state. `LobbyView` gains a header row showing the username and optional Discord avatar image. The `logout` function uses `try/catch/finally` rather than `try/finally` so network failures are swallowed; the client-side session is cleared unconditionally.

One notable test fix: the `useAuthStore.test.js` "logout clears currentUser even when the request fails" test was originally failing because `try/finally` propagates the rejection to the awaiting caller. Switching to `catch {}` + `finally` made the store's contract explicit — logout always succeeds from the caller's perspective, even if the server-side request fails. All 3281 tests pass; quality:strict clean.
