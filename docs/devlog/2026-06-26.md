# 2026-06-26

## 22:22 — PR: M9 Debt Sprint — Seven Deferred Items Closed

This PR closes seven tech-debt issues filed across M6–M8 that were deferred pending a dedicated cleanup pass. All changes are in one of three categories: correctness fixes to auth and notification code (#664, #652, #651, #650), test coverage improvements (#629, #652), and documentation/citation corrections (#627, #628).

The most substantive auth fix is #664: the new-join collision check in the join route previously only compared `side_a_faction` against the requested side. The invariant held in practice (the creator always claims `side_a`), but the check was brittle — if a future game mode ever allowed either player to create first, the guard would silently fail. The fix adds an `|| joinRow.side_b_faction === side` clause, making the guard robust to any column assignment. Several existing join-route tests had to be updated because they were exercising the route with the default mock (which has `side_b_faction: 'confederate'`) and sending `{ side: 'confederate' }`, relying on the old single-column check to pass through. Those tests now carry explicit open-slot mocks.

For the Discord notification path (#651 + #650): `notifyWebhook` previously skipped the `isAllowedDiscordWebhook` validation entirely when the `DISCORD_WEBHOOK_URL` development override was active. This meant a corrupted DB entry could POST to an arbitrary host as long as the dev override was set. The fix moves the stored-URL validation above the override resolution: the stored webhook must pass the Discord allowlist check before the function even considers where to POST. The override then redirects the validated traffic to the local sink without bypassing the egress guard. A companion test was added asserting that an invalid stored URL is rejected even when the override is set. Issue #650 (env var at module init vs call time) was already resolved by PR #661 — the current code reads the env var inside `notifyWebhook` at call time, so the issue required only a clarifying comment rather than a code change.

The arty-vs-arty CBF test (#629) replaced a structural placeholder (`expect(true).toBe(true)`) with a real fixture. The key insight was that the combat table produces no SP loss at roll 2 from the `'4-5'` column — roll 2 is the minimum attacker roll, not the maximum. Dice `[4, 4]` (sum 8) was chosen because that is the first roll in the `'4-5'` column that produces SP loss (`value = 1`). The new test gives the CSA defender unit `c1` a `gunType: 'H'` in the OOB fixture, causing `findOobUnit` to return an artillery entry and triggering the CBF marker path.

The morale cascade citation fix (#627) was informed by a domain-expert ruling: `LOB §6.3` is the Retreat rule, not a cascade mechanic. No LOB v2.0 or SM source document defines a morale cascade. All `LOB §6.3` citations in `cascadeMorale` and `resolvePendingMorale` have been replaced with "designer extension" notes, and the morale test descriptions updated in kind. The `pendingResolution.context.brigadeId` field was already present and verified by existing tests — the code was structurally correct but cited a non-existent rule. The hex-scoped resolution behavior is intentional for the house rule: non-routed hex co-occupants check morale when their brigade-mates rout.
