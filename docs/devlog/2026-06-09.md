## 09:40 — PR: feat(m5.5): multi-scenario platform (#529)

This PR delivers the full multi-scenario platform — the infrastructure needed for the app to
select, remember, route, load, and edit scenario-specific data rather than assuming South Mountain
everywhere. It closes issue #529 and completes the M5.5 milestone.

The central design decision was to introduce a single authoritative slug→folder map
(`SCENARIO_FOLDERS` in `scenarioFolders.js`) and a `resolveScenarioPath(slug, file)` function
that all server-side data access flows through. This makes the mapping trivially auditable and
means adding a new scenario later requires only one line in that map. The `ScenarioNotFoundError`
class carries a `status: 404` so Express middleware can surface it cleanly without a separate
lookup.

On the client, `useScenarioStore` (Pinia + localStorage) is the single source of truth for the
active scenario slug. `scenarioPath(suffix)` on the store builds canonical URLs, which both
`HomeView` nav links and `EditorNav` links consume. Editor views read `useRoute().params.scenarioSlug`
to build their API URLs dynamically — the map, OOB, and scenario editor composables each accept
an optional slug and fall back to the legacy tool endpoints when no slug is present, preserving
backward compatibility with the standalone tool URLs.

Vue Router was extended with `/scenarios/:scenarioSlug/...` parameterized routes for lobby, game,
and all five tool pages, plus legacy redirect rules from the old flat paths to `THG` so any
bookmarked or hardcoded links continue to work. Eight scaffold data folders (THG, TTS, AFS, LCV,
NBH, TTW, NTB, IB) were created with Zod-valid placeholder JSON, giving the server something to
serve and validating the data layout end-to-end.

A late fix was needed in `vite.config.js`: Vite defaults to reading `.env` from the client
package root (`client/`), but the project `.env` lives at the monorepo root. Adding
`envDir: '..'` makes `VITE_MAP_EDITOR_ENABLED` visible to the browser bundle, which gates the
Editor link on the home page. Non-SM scenario data and full round-trip browser testing are
deferred to M6 when individual scenario editors will be populated.
