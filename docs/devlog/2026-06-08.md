# 2026-06-08

## 12:13 — PR: Editor polish — nav cleanup, lighting schedule enhancements, turn structure rework

This PR closes issues #526 and #527, which were scoped together as a single conductor track. The
work falls into three distinct areas: navigation cleanup, lighting schedule feature additions, and
a substantive rework of how turn structure is modeled and displayed.

The navigation cleanup (#526) removed redundant inline nav links that had accumulated beside the
header of each tool view. These links were superseded by the EditorNav top bar introduced in M5.5,
but the old per-view links were never removed. All five tool views were swept, and the Scenario
Editor was also wired up to EditorNav for the first time — it had been omitted from the original
implementation. The EditorNav component was updated to include Scenario Editor as its first link.

The lighting schedule feature additions (#527) added two things: fog and rain as first-class
lighting conditions (joining day, twilight, night), and a `visibilityHexes` field on each lighting
entry. The `visibilityHexes` field replaces the earlier `nightVisibilityCap` scalar, which was
architecturally wrong — visibility can vary independently of condition and the per-entry model is
more expressive. Default visibility values are auto-applied when a condition is selected (day→999,
night→2, fog/rain/twilight→4). A Time column was also added to the lighting schedule table showing
the calculated clock time for each `startTurn`, derived using per-condition turn durations.

The turn structure rework removes `minutesPerTurn` as a single scalar from the schema and
`scenario.json`. LOB §1.1 specifies day and twilight turns as 15 minutes and night turns as 30
minutes — a single scalar cannot represent this split. `totalTurns` is now a computed read-only
display in the scenario editor, derived by walking turn-by-turn through the lighting schedule and
accumulating per-condition durations. The `lastTurn` field is correctly interpreted as the start
time of the final turn (not game-end), so 09:00–20:00 with all-day turns computes to 45 turns. The
lighting schedule `startTurn` values in `scenario.json` were also corrected from turn 28/31 (based
on the wrong 20-min assumption) to turn 39/41 (~18:30 and ~19:00 respectively), flagged as
historical estimates pending verification against the physical SM Hour Track.

A storage key bump from v2 to v3 was included to evict stale localStorage drafts that pre-dated
`visibilityHexes` — those drafts would trigger a 400 on push because the server schema now requires
the field on every lighting entry. The server also needed a restart mid-session because it was
running the old schema that still required `minutesPerTurn`; that issue will not recur after the
PR is merged since the schema is the source of truth for a fresh boot.
