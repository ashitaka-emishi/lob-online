# 2026-06-17

## 17:28 — PR: Pre-M7 Debt Sprint A — bugs, security, and high-score fixes

Sprint A closes ten of the highest-risk tech-debt items accumulated during M6, reducing the net open debt score from 49 to 43. The sprint was structured in three phases — OOB consolidation first (prerequisite for the cascade fixes), then rules-engine correctness bugs, then security and reliability hardening — with quality gates run after each phase and a checkpoint requiring human approval between phases.

The most consequential rules fix was the combat column SP bug (#604): `handleFireCombat` was using OOB printed strength points for the column lookup rather than the unit's current SP count after losses. This meant a badly mauled regiment still fired at full printed strength — a significant rules error that would have produced materially wrong combat outcomes once SP tracking became active in M7. The fix is a one-line change (`au.strengthPoints ?? oobUnit.strengthPoints`) but the test harness required care: `finalColumn` is a string label like `"4-5"`, not a number, so inequality assertions needed to be `not.toBe` (different column) rather than `toBeLessThanOrEqual`.

The soft-lock fix (#571) was architecturally more invasive: `getValidActions` was returning `[]` for `closingRoll` and `moraleCheck` pending types, leaving the game in a state where no action was valid. The fix extends the RESOLVE_MORALE gate to all three morale-family pending types, and `resolvePendingMorale` in `morale.js` now derives the target hex from whichever context field is present (`defenderHex` for fire/close combat, `hex` for cascade checks). The `closingRoll` and `moraleCheck` handlers don't fully resolve their outcomes yet (full retreat and cascade mechanics are M7 work), but the soft-lock is gone and the morale dice roll is accepted.

The `cascadeMorale` hex-scope fallback bug (#606) was subtle: the original code entered degraded hex-scope mode whenever `findBrigadeForUnit` returned null, which includes corps-level units and batteries that legitimately aren't in any brigade. The fix restructures the function to check `if (!oob)` up front for the degraded path, then silently skips units not found in any brigade rather than triggering the fallback. The OOB consolidation in Phase 1 (#573, #600) was a prerequisite: extracting `findOobLeader` and `findBrigadeForUnit` into `oob.js` both eliminates the duplicate implementations and makes the cascade fix cleaner to reason about.

Security hardening added the attacker-side ownership check that was obviously missing (#603): a player could fire with enemy units by submitting their hex as the attacker. The fix adds one guard after OOB side resolution. The rate limiter split (#589) and trust-proxy config round out the security improvements. One intentional constraint: the `TRUST_PROXY` opt-in is env-var gated rather than always-on, so dev environments don't accidentally trust proxy headers from untrusted sources.

## 20:35 — PR: Pre-M7 Debt Sprint B — test gaps, traceability, and score-1/2 cleanup

Sprint B closes the remaining sixteen score-1/2 tech-debt items from M6, reducing net open debt from 43 to 24. The sprint ran in four phases: test fixes and traceability corrections first (low-risk, no logic changes), then engine refactors, then client reliability, then debt register closeout. All changes were committed to `feat/pre-m7-debt-sprint-b` and received a full five-dimension team-review plus a targeted second-pass on the fix commit before merge.

The most impactful engine change was extracting `sumCurrentSPs` into `oob.js` (#614), which eliminated a 14-line SP-halving loop duplicated across `fireCombat.js` and `closeCombat.js`. The helper accepts an `applyDgHalving` flag: `true` for the §5.0 fire-combat path (DG units halve their contribution to the combat column), `false` for the §7.0 close-combat gate (raw current SP, unmodified for DG). An `O(1)` index pair (`buildUnitIndex`/`findOobUnitFast`) was also added to `oob.js` to set up the hot-path replacement planned for M7 (#596). These helpers shipped with full parity and branch tests added by the second-pass fix commit. The client reliability fix (#588, #591) converted the `useGameStore` scenario fetch from fire-and-forget to awaited, surfacing errors via `console.warn` instead of swallowing them silently.

The traceability pass revealed a cluster of citation errors that the domain reviewer escalated to High/Medium severity: `moraleCheckRequired: true` in `closeCombat.js` was citing §6.0 (the morale intro, which says checks only happen when called for by the Combat Table) rather than §7.0a(f) (the specific Charge Sequence step that mandates an unconditional check); the 4-SP gate and automatic SP loss were citing §7.0c (MP gate for charging) instead of §7.0a(e)/§7.0 prose; and DG-halving throughout was citing §5.3 (Specialized Fires) instead of §5.0 (Combat Procedure). All three were corrected in the fix commit after the primary review. The CBF-clearing citation family (§8.1 → §5.8c) was also corrected consistently across `closeCombat.js`, `rally.js`, and `rally.test.js`.

One domain divergence was identified and flagged but intentionally deferred: the engine applies each unit's own morale rating when resolving a hex-wide morale check (§6.1 says the stack's TOP combat unit provides the rating for a single shared check applied to all units). A comment noting the divergence and its pre-existing nature was added to the test, and the issue is tracked in the domain-expert backlog for correctness review before M7 closes. The debt register after Sprint B stands at 8 open items (score 24), concentrated in rules-engine domain-verification items that require playtest validation rather than code changes.
