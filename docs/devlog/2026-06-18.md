# 2026-06-18

## 00:39 — PR: M7 Special Rules + Victory Conditions

This PR completes milestone M7, wiring the remaining LOB v2.0 and South Mountain rules into the
live game loop so that a full 45-turn South Mountain game can be played through to a scored
outcome. It covers five implementation phases: morale resolution enhancements (retreat + SP
losses), interactive rally rolls, artillery action pipeline, end-of-turn accounting, and VP
tracking with game-over detection.

The biggest design decision in the morale and retreat phase (Phase 1) was where retreat resolution
should live. We kept it as a pure helper in `engine/retreat.js` that takes explicit map data and a
current unit state, rather than embedding it inside the morale handler. This keeps the SP-loss and
retreat side-effects composable and testable without needing a full game state. The LOB §9.1a
leader-loss-check bug (#617) was fixed in the same phase: the check was firing only on the
defender's SP loss but the rule applies equally to the attacker's Opening Volley SP reduction.

Artillery (Phase 3) introduced the `LIMBER`, `UNLIMBER`, `FIRE_ARTILLERY`, and
`REPLENISH_ARTILLERY` actions. The unlimber range gate (LOB §3.6b: ≥5 hexes from enemy, or ≥4
with an Artillery Leader per LOB §9.1c) is enforced in the handler when `mapData` is available and
skipped in tests via injected OOB. The `FIRE_ARTILLERY` handler sets `pendingResolution` rather
than immediately resolving combat, consistent with how fire and close combat results are handled
elsewhere — resolution requires the player to submit dice. Canister ammo is gated to ≤3 range
(LOB §8.2a) and shell depletion uses the left/right column band logic from the Artillery Fire
Table.

End-of-turn accounting (Phase 4) required the most architectural thought. Attack Recovery
(LOB §10.8c) needs interactive dice but must fire in the Command Phase before order issuance, so
`drainAutoSteps` was extended with a `ctx` parameter that passes scenario and OOB context down
from `dispatch`. Variable reinforcements (SM §7.0) are resolved at `initGameState()` via a
`rollFn` injection point rather than during play — this avoids a setup-phase action that would
have no `activePlayer`. Random events (SM §7.1–7.2) are auto-rolled by `drainAutoSteps` when
entering the ATTACK_RECOVERY step; the result is stored as `pendingRandomEvent` on `ordersPhase`
and cleared by `ACKNOWLEDGE_RANDOM_EVENT`. Loss Recovery (LOB §9.3) is correctly disabled for SM:
the game ends at turn 45 (~20:00), and midnight (the recovery trigger) is never reached.

Victory point tracking (Phase 5) introduced `computeVP`, `computeTerrainVP`, `computeWreckVP`,
`evaluateVictory`, `isVpControlEligible`, and `updateHexControl` in `engine/vp.js`. Terrain
control follows SM §5.1 — the last qualifying unit (non-Routed infantry or unlimbered artillery)
to occupy a VP hex claims it; cavalry and Routed units do not count. Wreck VP (SM §5.2) is
additive: per-brigade VP stacks with division-level bonus VP when the whole division is wrecked.
The terminal game state uses `status: 'complete'` with all phase envelopes null — the
`GameStateSchema` refine was updated to allow this. The `VpPanel.vue` sidebar component shows
live VP totals per side; a full-screen overlay appears when `state.gameOver` becomes true.
