## 19:54 — PR: Pre-M8 Debt Sprint — Artillery Depletion Fix + Leader Loss Ruling (#633 #617)

This PR closes the two rules-correctness items identified as pre-M8 prerequisites during the M7
closeout. Both required domain-expert rulings before any code could be written, which is why they
were deferred from M7 proper rather than fixed in place.

**#633 — Artillery depletion zone semantics inverted.** The core bug was in `combat.js`: the
column sets `LEFT_DEPLETION_COLUMNS` and `RIGHT_DEPLETION_COLUMNS` encoded the wrong mental model.
The LOB Charts Combat Table (lob-tables.pdf p.2) has two color zones — an orange zone (numeric
columns `-B, -A, 1, 2-3, 4-5, 6-8`) that depletes whichever ammo type was actually fired, and a
blue zone (lettered columns `A, B, C, D`) that depletes canister only with no depletion at all if
shell was fired. The previous code treated the left half of numeric columns as
"shell-depletes-regardless" and grouped `4-5` and `6-8` with the blue/canister-only zone — wrong
on both counts. The fix renames the sets to `ORANGE_DEPLETION_COLUMNS` and
`BLUE_DEPLETION_COLUMNS`, moves `4-5` and `6-8` into the orange set, and rewrites the
depletion block in `artillery.js` to apply the correct ammo-typed logic. A silent secondary bug
was also fixed: `fireCombat.js` was checking `depletionBand === 'left'` which was always false
after the rename, meaning infantry fire depletion markers were never being set.

**#617 — Leader loss scope confirmed correct, no code change.** The concern was whether cascade
morale SP losses (from `resolveMorale.js`) should also trigger the §9.1a Leader Loss check. The
domain-expert ruling was unambiguous: the LOB Charts Charge Sequence places leader loss checks at
steps 1 (Opening Volley) and 2 (§7.0c automatic defender loss), with the morale check at step 3.
Cascade losses at step 3 do not loop back to trigger another leader loss check. The existing gate
`leaderLossCheckRequired: defenderSpLoss > 0 || ovSpLoss > 0` is correct. The only change is a
citation comment added to `closeCombat.js` to explain why cascade losses are intentionally excluded
— future readers now have the ruling in context rather than having to re-derive it.

The debt register required a full reconciliation pass because this is the first PR landing directly
on master since PR #632. Five issues (#612, #613, #616, #618, #621) that were closed on GitHub
during the Pre-M7 and M7 implementation work were still listed as open in the register. This PR
removes all seven items (#633, #617, plus the five stale closures), dropping the net open score
from 31 to 10 across 3 remaining items. All three remaining items (#562, #563, #634) are M8
deliverables — no current-milestone open debt remains.

TDD discipline was followed throughout: failing tests were written first for all four depletion
zone cases (orange+shell, orange+canister, 4-5+shell, 6-8+canister), confirmed red, then the
implementation was written to pass them. The blue-zone + shell → no-depletion path cannot be
exercised through the artillery handler (artillery range shifts are zero or negative, so the
lettered A-D columns are only reachable via terrain/formation shifts deferred to M8). That case is
covered in `combat.test.js` via direct `combatResult()` calls with explicit right-shifts.
