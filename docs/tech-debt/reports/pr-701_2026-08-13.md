## Fixed Findings

Fixed in place: all 7 High-severity findings plus the security-flavored Medium findings, per
explicit user scoping decision ("fix all Highs + security Mediums now, defer the rest").

Highlights:

- Login CSRF (missing OAuth `state` parameter) — real vulnerability, verified via
  `passport-oauth2`'s `NullStore.verify()` unconditionally returning `true` with no state
  configured.
- `.env.example` shipping `AUTH_DEV_MODE=true` as the default (introduced earlier in this same
  branch pickup), combined with a `dev-` session bypass in `deserializeUser` that had no
  runtime check of the flag at all — a session minted while the flag was on kept
  authenticating for its full 14-day lifetime after being turned off. Both fixed; the mount
  guard also hardened with an independent `NODE_ENV !== 'production'` check.
- Identity recorded (`side_a_user_id`/`side_b_user_id`) but never checked for authorization —
  possession of a sideToken alone authorized side access regardless of Discord identity.
- Logout (or session expiry — a real scenario for a multi-day correspondence wargame)
  permanently locked the game owner out via a 409 "Side already taken" on rejoin, with no
  recovery path. Added an identity-based reclaim flow instead of just closing the
  authorization gap.
- `DELETE /:id` gained an ownership check, closing a previously-documented residual risk
  (#410 item 1, #688) now that the data exists to close it.
- Client auth bootstrap only ran on `requiresAuth`-guarded routes — the OAuth callback
  redirect to `/` never populated auth state, so `HomeView` showed "logged out" until the
  user happened to navigate somewhere guarded.
- Also fixed independently, before review even started: a live smoke test caught
  `req.session.regenerate()` silently dropping the passport login on every create/join
  (mutation-verified fix + a subsequent review finding that the original regression test's
  assertion didn't check call _ordering_, only that `login` was eventually called — a
  reordering would have silently reintroduced the bug).

Full mutation-verification discipline applied throughout: every new/changed regression test
was confirmed to actually fail when its target fix was reverted, not just written to pass.
