# Specification: CI Environment Fix — Lockfile Drift + Deploy Workflow Guard

**Track ID:** ci-env-fix_20260622
**Type:** Chore
**Created:** 2026-06-22
**Status:** Draft

## Summary

CI has been broken on every branch since 2026-06-16 due to `package-lock.json` drift: `rolldown@1.0.0-rc.17`
(transitive dep of `vite@8`) upgraded its nested `@emnapi/core`/`@emnapi/runtime` sub-deps from `1.10.0` →
`1.11.1` on the npm registry, but the committed lockfile still pins `1.10.0`. Fix the lockfile, then address
the Deploy workflow's "missing server host" failure caused by unconfigured M8 infra secrets.

## Context

M8 has not started yet — the DigitalOcean Droplet and its associated GitHub secrets (`DO_DROPLET_IP`,
`DO_SSH_USER`, `DO_SSH_KEY`) are M8 deliverables. The deploy workflow has been failing with a hard error on
every master push since the workflow was introduced. The CI workflow (`npm ci`) failure is the blocking issue —
no branch can pass CI, which means branch protection is effectively bypassed on every merge.

## Problem Description

**Issue 1 — Lockfile drift (CI failure):**

- Symptom: `npm ci` exits 1 with `Missing: @emnapi/core@1.11.1 from lock file` / `Missing: @emnapi/runtime@1.11.1`
- Root cause: `rolldown@1.0.0-rc.17` (pulled by `vite@8.0.10`) declared updated sub-dep versions that weren't
  committed to the lockfile. `npm ci` requires exact lockfile parity and fails immediately.
- First failure: 2026-06-16 (Dependabot branch was last green run)
- Fix: run `npm install` locally, commit the updated `package-lock.json`

**Issue 2 — Deploy workflow hard failure (missing secrets):**

- Symptom: `error: missing server host` on every master push
- Root cause: `DO_DROPLET_IP` GitHub secret not configured — M8 infra not yet provisioned
- Fix: add an `if` condition to skip the deploy job when the secret is absent, or add a `continue-on-error`
  guard with a clear comment that the job requires M8 secrets

None — this is a standalone environment fix.

## Out of Scope

- Wiring the actual DigitalOcean secrets or provisioning M8 infra
- Upgrading any runtime or dev dependencies beyond what `npm install` naturally resolves
- Any game-engine, schema, or application code changes

## Technical Notes

The lockfile fix is `npm install` (not `npm update`) — this resolves the missing nested deps without
upgrading anything that isn't already floating. Only `package-lock.json` should change; `package.json`
should be unmodified.

For the deploy workflow guard, the idiomatic GitHub Actions approach is:

```yaml
if: ${{ secrets.DO_DROPLET_IP != '' }}
```

on the job, which skips it cleanly when the secret is absent rather than failing.
