# Specification: M8 Persistence + Auth Hardening

**Track ID:** m8-persistence_20260622
**Type:** Feature
**Created:** 2026-06-22
**Status:** Draft

## Summary

Replace local-file game state persistence with DigitalOcean Spaces (S3-compatible), add
history log appending, migrate the SQLite schema to add faction-binding and discord_webhook
columns, and enforce side tokens at join/re-join to prevent impersonation.

## Context

The current store layer writes game state to `data/games/<id>/state.json` on the local
filesystem. That doesn't survive server restarts in production. The SQLite `games` table
needs `side_a_faction`, `side_b_faction`, and `discord_webhook` columns. The join path
currently allows side-switching on re-join — that needs to be locked down.

These two concerns (Spaces store + SQLite hardening) ship together because separating them
creates a window where the store is swapped but auth is still broken — an awkward half-shipped
state. One Checkpointed review covers both.

## Acceptance Criteria

- [ ] Game state survives a server restart (loaded from Spaces on each request)
- [ ] History log grows correctly (`000001.json`, `000002.json`, …) in Spaces with each action
- [ ] Version conflict on concurrent save raises an error (optimistic concurrency preserved)
- [ ] `store/index.js` remains the single import point; `gameFile.js` no longer exported
- [ ] SQLite migration runs idempotently (safe to restart mid-migration)
- [ ] Side tokens bound to factions at create/join time
- [ ] Re-join with a different side than originally chosen returns 403
- [ ] `POST /api/v1/games` accepts optional `discordWebhook` URL and persists it to SQLite
- [ ] All existing tests pass; new modules have ≥ 70% line coverage
- [ ] `npm run quality:strict` passes
