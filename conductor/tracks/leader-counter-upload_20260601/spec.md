# Specification: Leader Counter Image Upload

**Track ID:** leader-counter-upload_20260601
**Type:** Feature
**Created:** 2026-06-01
**Status:** Draft

## Summary

Wire the `CounterImageWidget` upload flow to leader nodes in the OOB editor so that scenario creators can assign counter images to leader units, updating `leaders.json counterRef.front` and displaying real counters on the game map.

## Context

PR #475 added a fallback counter rect for leader units whose `counterRef.front` is null in `leaders.json` (Pleasonton, DH Hill, GB Anderson, Garland, etc.). These leaders now appear on the map as labeled placeholders. The `CounterImageWidget` is already functional for brigade/artillery nodes but is not wired to leader nodes. Leader data lives in `leaders.json` (separate from `oob.json`) with its own PUT route at `/api/tools/leaders-editor`.

Root cause investigation revealed two gaps:

1. `selectNode` in `useOobStore.js` only searches `oob.value` via `findNodePath`, returning null for leader nodes — so `selectedNodePath` is null for leaders and the `v-if="nodePath"` guard in `OobDetailPanel` hides the widget entirely.
2. Even with a fixed path, the regular `front`/`back` slots only cycle through the static `countersManifest.js` (no upload button). Leaders whose counter files do not yet exist in the manifest need a Browse/Upload button.

## User Story

As a scenario creator, I want to assign counter images to leader units in the OOB editor so that leaders display their real counters on the game map instead of fallback placeholders.

## Acceptance Criteria

- [ ] Leader nodes in the OOB editor tree show a counter image upload widget (same as brigade nodes)
- [ ] Uploading sets `leaders.json counterRef.front` for that leader
- [ ] Game map displays the real counter image on next load
- [ ] Leaders without an uploaded image continue to show the fallback rect (no regression)

## Dependencies

- `CounterImageWidget` — existing component, currently wired to OOB store/brigade tree only
- `/api/tools/leaders-editor` PUT route — existing, already saves `leaders.json` changes
- `/api/tools/counters/upload` POST route — existing, writes files to `client/public/counters/`
- PR #475 fallback counter rect — merged

## Out of Scope

- Changes to brigade, artillery, or any non-leader unit types

## Technical Notes

- Root cause: `findNodePath(oob.value, node.id)` in `selectNode` returns null for leaders; fix by also searching `leaders.value` and prepending `leaders.`
- Browse/Upload buttons should be added to the front/back slots in `leader` mode, reusing `POST /api/tools/counters/upload`
- After upload, the new file won't appear in `countersManifest.js` until the next Vite restart (manifest is regenerated at build/dev start); the game map renders the counter correctly regardless since it doesn't use the manifest
- Refs: PR #475 (fallback counter rect), #202 (CounterImageWidget original), issue #484
