## Phase 1: Fix leader node path detection

`useOobStore.js` `selectNode()` calls `findNodePath(oob.value, node.id)` and uses the result as-is. Leaders are in `leaders.value`, not `oob.value`, so this always returns null. The widget is never rendered.

### Tasks

- [x] Task 1.1: In `useOobStore.js` `selectNode()`, after `findNodePath(oob.value, node.id)` returns null, call `findNodePath(leaders.value, node.id)` and prepend `'leaders.'` to produce `leaders.<path>` (e.g. `leaders.union.0`)
- [x] Task 1.2: Write a unit test for `selectNode` that covers: (a) brigade node → OOB path returned, (b) leader node → `leaders.union.N` path returned, (c) unknown node → null
- [x] Task 1.3: Verify `OobDetailPanel` renders `CounterImageWidget` for a leader node in the test environment (jsdom mount, check widget appears)

### Verification

- [x] Selecting a leader node sets `store.selectedNodePath` to `leaders.<side>.<index>`
- [x] `v-if="nodePath"` guard passes and widget renders

## Phase 2: Add Browse/Upload for front/back slots in leader mode

The `front`/`back` slots only support keyboard cycling through `ALL_COUNTERS`. Leaders whose counter files don't exist in the manifest need an upload button. The promoted-slot upload mechanism (`onPromotedFileSelected`) can be reused.

### Tasks

- [x] Task 2.1: In `CounterImageWidget.vue`, add a `standardFileInput` ref and `activeStandardFace` ref for the standard (non-promoted) upload path in leader mode
- [x] Task 2.2: Add "Browse…" buttons to the `front` and `back` slot footers, rendered only when `mode === 'leader'`; clicking calls a new `browseStandard(face)` function
- [x] Task 2.3: Implement `onStandardFileSelected(e)` — upload via `POST /api/tools/counters/upload`, then call `store.updateCounterRef(nodePath, { ...base, [activeStandardFace.value]: data.filename })`
- [x] Task 2.4: Write tests: upload sets `counterRef.front` correctly; fallback `getDefaultCounterRef()` shape is used when `counterRef` is null; upload error logs but does not corrupt state

### Verification

- [x] Clicking Browse on the Front slot, selecting a file: (a) POSTs to `/api/tools/counters/upload`, (b) updates `counterRef.front`, (c) marks store dirty
- [x] Leaders without a `counterRef` still show the fallback rect (no regression from null counterRef)
