# Specification: M8 MinIO Init — Auto-Create Dev Bucket on docker compose up

**Track ID:** m8-minio-init_20260623
**Type:** Chore
**Created:** 2026-06-23
**Status:** Draft

## Summary

Add a `minio/mc` companion service to `docker-compose.yml` that automatically creates the
`lob-online-dev` bucket on first run, and add a healthcheck + restart policy to the MinIO
service. Closes #640 (score 3) and #642 (score 1).

## Context

The MinIO service starts without creating any buckets. First-run developers hit `NoSuchBucket`
from the Spaces client with no documented remedy until they manually visit the console at
port 9001. The `minio/mc` image provides a standard pattern for init containers that wait for
MinIO to be healthy and then create required buckets. Bundling #642 (healthcheck) here makes
sense because the init container's `depends_on: condition: service_healthy` requires the
healthcheck to exist.

## Technical Notes

- Standard pattern: `minio/mc` image, entrypoint that runs `mc alias set` then `mc mb --ignore-existing`
- The init service should use `depends_on: minio: condition: service_healthy` so it waits
  for MinIO to be ready before attempting bucket creation
- Set `restart: "no"` on the init container so it doesn't loop after the bucket exists
- The healthcheck command: `mc ready local` or `curl -f http://localhost:9000/minio/health/live`
