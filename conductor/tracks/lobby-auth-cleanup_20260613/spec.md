# Specification: Lobby and Auth Cleanup — Side Entry Flow and Session Guard

**Track ID:** lobby-auth-cleanup_20260613
**Type:** Feature
**Created:** 2026-06-13
**Status:** Draft

## Summary

Fix the lobby game-start and side-selection UX so players can create and enter games cleanly (#549), and harden game routes so a session for one game cannot access a different game (#553).

## Context

M5 added `LobbyView` and session-based game joining, but the lobby UX assigns the creator to Confederate (unexpected), disables side buttons once a game exists (blocking entry), and the game routes do not verify that the session's `gameId` matches the route parameter. These two fixes clean up the M5 session foundation before M6 starts.

## User Story

As a player, I want to click **New Game** to immediately enter a game as Union, and click **USA** or **CSA** to enter an existing game from the correct side, so that I can start playing without manual workarounds.

## Acceptance Criteria

### Lobby flow (#549)

- [ ] Clicking **New Game** creates a game, routes to `GameView`, and reports `side: "union"` for the creator session.
- [ ] Clicking **USA** for an existing game routes to that game and sets the session to `side: "union"`.
- [ ] Clicking **CSA** for an existing game routes to that game and sets the session to `side: "confederate"`.
- [ ] USA/CSA buttons remain available for existing games (not disabled once a game exists).
- [ ] Lobby copy and button labels reflect the new flow.
- [ ] Tests cover: new-game creator side, USA entry, CSA entry, routing, active-game button behavior.
- [ ] Existing lobby and game route tests continue to pass.

### Session guard (#553)

- [ ] `GET /api/v1/games/:id` succeeds for a same-game session.
- [ ] `GET /api/v1/games/:id/actions` succeeds for a same-game session.
- [ ] `POST /api/v1/games/:id/actions` succeeds for a same-game session when the action is legal.
- [ ] Each guarded route returns 403 for a different-game session.
- [ ] Each guarded route returns 401 for a missing session.
- [ ] Route tests cover same-game, different-game, and missing-session cases for all three routes.

## Technical Notes

The session guard should be a small middleware function applied to the three listed routes. Check `req.session.gameId === req.params.id`; if the session has a `gameId` that doesn't match, return 403. If the session has no `gameId`, return 401. Place it after the existing session-existence check so existing tests for unauthenticated requests continue to work.

The new-game creator side fix is a one-line change to the `POST /api/v1/games` handler — set `side: 'union'` for the creator. Update the comment and any seed data or test fixtures that assume Confederate.
