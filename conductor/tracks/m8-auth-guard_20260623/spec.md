# Specification: M8 Auth Guard — requireSide on DELETE Route

**Track ID:** m8-auth-guard_20260623
**Type:** Chore
**Created:** 2026-06-23
**Status:** Draft

## Summary

Add `requireSide` middleware to the `DELETE /api/v1/games/:id` route, closing the critical
security gap where any unauthenticated caller with a game UUID can permanently destroy a game
and its Spaces state object. Closes #648 (score 5).

## Context

Every other state-touching route (`GET /:id`, `GET /:id/actions`, `POST /:id/actions`) already
mounts `requireSide`. The DELETE route was left unguarded during single-player scaffolding.
With M8 persistence shipping real Spaces-backed game state, an unguarded delete endpoint is a
production security risk — any caller who knows a game UUID (handed out by `GET /api/v1/games`)
can destroy any game's data permanently.

## Technical Notes

- The fix is literally one word: add `, requireSide,` as the second argument to `router.delete`.
- `requireSide` populates `req.game` on success; the handler can use `req.game` instead of
  re-fetching from the DB (consistent with other guarded routes).
- Tests: existing DELETE tests will need a valid sideToken in the session to pass. Check
  `games.test.js` for the DELETE test block and add auth setup matching the pattern used
  by the actions route tests.
- **Interaction Mode: Checkpointed** — touches auth surface; pause before applying any
  test changes that weaken auth assertions.
