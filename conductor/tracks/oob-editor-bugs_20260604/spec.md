# Specification: OOB Editor Display/Data Bugs (#506)

**Track ID:** oob-editor-bugs_20260604
**Type:** Bug
**Created:** 2026-06-04
**Status:** Draft

## Summary

Four display and data bugs in the OOB Editor found during M6 pre-work: missing back-counter slot for Supply/HQ nodes, AotP HQ synthetic node not selectable, Walker (Promoted) appearing as a phantom top-level node, and `specialRules` rendering as `[object Object]`.

## Context

The OOB Editor was delivered in M2 and extended in M5 (leader counter image upload). These bugs are regressions or gaps in M2–M5 surfaces. Fixing them before M6 keeps the editor usable for scenario data entry during combat/morale implementation.

## Problem Description

### Bug 1 — Supply and HQ nodes have no back-counter slot

Selecting a Supply or HQ node shows `CounterImageWidget` but only the front slot. Back slot is hidden because the widget only renders it when `mode="leader"` is set. `OobDetailPanel.vue:260–265` calls the widget without a `mode` prop for HQ/supply nodes.

### Bug 2 — AotP HQ node shows "Path not resolvable" error

The AotP HQ is a synthetic node injected by `oobTreeTransform.js:224` as `_hq: { id: 'usa-army-hq', name: 'AotP HQ' }`. This object has no entry in `oob.json`, so `findNodePathInTree` returns `null`, and `OobDetailPanel.vue:267–271` renders the fallback error message instead of the counter widget.

### Bug 3 — CSA "Col Joseph Walker (Promoted)" appears as a standalone node

Walker's promoted variant (`walker-promoted`, `baseLeaderId: "walker"`) in `succession.json` should appear only as a child under the Walker leader node. It is instead appearing as an independent peer node in the CSA tree.

### Bug 4 — Special Rules field displays "[object Object]" for leaders

`leaders.json` stores `specialRules` as a JSON object. `OobDetailPanel.vue:332` binds the textarea with `:value="node.specialRules ?? ''"`, which coerces an object to the string `"[object Object]"`.

## Acceptance Criteria

- [ ] Supply and HQ nodes show both a front and back counter image slot in the OOB editor.
- [ ] Clicking the AotP HQ node opens the counter image widget (no "path not resolvable" fallback).
- [ ] "Col Joseph Walker (Promoted)" appears only as a child variant under Walker, not as a standalone top-level node.
- [ ] Selecting a leader with a structured `specialRules` object displays it as pretty-printed JSON in the textarea, and saving parses it back to an object correctly.

## Technical Notes

For Bug 2, the preferred approach is to forward an explicit `nodePath` from `OobTreeNode` for synthetic nodes rather than relying on `findNodePathInTree` to resolve them. For Bug 4, pretty-print on display with `JSON.stringify(node.specialRules, null, 2)` and parse on save with `JSON.parse`.
