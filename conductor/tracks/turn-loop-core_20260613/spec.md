# Specification: Turn Loop Core — Engine, Store, and ActionPanel Payload Wiring

**Track ID:** turn-loop-core_20260613
**Type:** Feature
**Created:** 2026-06-13
**Status:** Draft

## Summary

Wire concrete valid-action candidates with payloads through the engine, into the Pinia store, and into the ActionPanel UI so that command, activation, and order actions can be submitted with proper payloads — not just broad type names.

## Context

M5 delivered the turn reducer, `getValidActions`, and `ActionPanel`, but valid actions are broad type strings with no payload data, the store does not own valid-action state, and ActionPanel cannot submit payload-bearing actions. This track closes those three gaps before M6 combat work begins.

## User Story

As a player in GameView, I want to click an action button and have the correct payload (unit ID, hex, order type) automatically included, so that I can progress through the turn loop without manually constructing payloads.

## Acceptance Criteria

### Engine (#550)

- [ ] `getValidActions(state, playerSide)` returns `ROLL_INITIATIVE` candidates with `{ leaderId, unitId }`.
- [ ] Returns `ISSUE_ORDER` candidates with `{ unitId, orderType }` for `attack` and `move`.
- [ ] Returns `ACTIVATE_STACK` candidates with `{ hex }` for eligible un-activated stacks.
- [ ] Returns `END_ACTIVATION` only when there is a current activation.
- [ ] Returns `END_PHASE` when legal.
- [ ] Returns no valid actions for the wrong-side player.
- [ ] Returns no valid actions for pending-resolution states.
- [ ] Excludes already-activated stacks from activation candidates.
- [ ] All above behaviors are covered by engine unit tests.

### Store (#552)

- [ ] `useGameStore` owns `validActions` (not local component state).
- [ ] `useGameStore` exposes `refreshValidActions(gameId)`.
- [ ] Out-of-order valid-action refresh responses cannot overwrite newer state (generation guard).
- [ ] Socket-triggered refresh updates both game state and valid actions.
- [ ] `GameView` consumes valid actions from the store, not local state.
- [ ] Out-of-order and socket-triggered behaviors are covered by tests.
- [ ] ActionPanel behavior does not regress.

### ActionPanel UI (#551)

- [ ] `END_PHASE` remains a one-click action.
- [ ] `ROLL_INITIATIVE` submits a valid `{ leaderId, unitId }` payload.
- [ ] `ISSUE_ORDER` submits a valid `{ unitId, orderType }` payload for `attack` or `move`.
- [ ] `ACTIVATE_STACK` submits a valid `{ hex }` payload from the selected stack/hex.
- [ ] `END_ACTIVATION` remains one-click when active.
- [ ] UI prevents null/invalid payload submissions.
- [ ] Payload construction and invalid/disabled states are covered by tests.
- [ ] At least one GameView integration test covers a payload-bearing action.

## Dependencies

- Existing `engine/phase.js` — `getValidActions` to be extended.
- Existing `useGameStore` and `GameView` — to be refactored.
- Existing `ActionPanel.vue` — to be extended.

## Out of Scope

- Combat, morale, rally, artillery, victory conditions, random events, reinforcements.
- Production auth hardening.
- E2E smoke tests (track: turn-loop-polish_20260613).
- Lobby and session flow changes (track: lobby-auth-cleanup_20260613).

## Technical Notes

The generation guard in the store should use a monotonic counter incremented on each refresh call; discard responses whose generation is less than the current counter. Socket-triggered refresh should call `refreshGame` and `refreshValidActions` together, or merge them into a single refresh path.
